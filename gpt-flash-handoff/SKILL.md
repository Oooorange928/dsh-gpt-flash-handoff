# GPT 规划 → Flash 执行 → GPT 独立验收 → 用户交接

本技能把「GPT 主模型规划、DeepSeek V4.1 Flash 执行、GPT 独立验收、向用户交接」这一协作模式固化为可移植的提示层约定与可填写模板。

**本技能是提示层约定，不是引擎级调度。** 安装本技能不会自动为所有任务启用、也不会自动创建任何子代理；是否使用、何时使用由 GPT 主模型按下面的判定规则决定。系统/开发者指令、工具权限与审批、用户当前任务的明确限制，优先级均高于本技能。

## 0. 适用与不适用

- **适用**：当前主模型是 GPT 系列，且任务被判为「较复杂」（见第 1 节）。
- **只对 GPT 主代理生效**：本技能只约束**充当主模型（主代理）**的 GPT 会话；发起派发的一方才有第 2 节的契约义务与第 5 节的验收责任。
- **执行子代理不适用、也不递归触发本技能**：被派发出去的 Flash 执行子代理不是「GPT 主模型」，它不加载本技能、不按本技能判定复杂度、不再创建任何子代理；契约中必须写明「不得递归委派」（见第 4 节）。
- **不适用**：主模型不是 GPT 系列；当前会话是执行子代理；任务简单；用户在当前任务中明确要求独立完成或禁止委派（见第 9 节）。

## 1. 复杂度判定：不强行派发

在实质执行前，结合以下四个维度判断复杂度，**不要为套流程强行创建子代理**：

| 维度 | 偏简单（GPT 直接做） | 偏复杂（规划 + 派发 Flash） |
| --- | --- | --- |
| 范围 | 单文件、单次问答、单条只读查询 | 跨文件/跨模块修改，或大批量产物生成 |
| 依赖 | 无阶段依赖，一步到位 | 多阶段依赖、需按序推进，或批量检索与分析 |
| 风险 | 可回退、无外部副作用 | 涉及设计决策、复杂调试，或易错的高耦合改动 |
| 验证成本 | 一眼可验，无需复跑 | 需要写/跑测试、构建、比对来源与数值 |

判定规则：

- 四个维度**整体偏简单**时直接处理，不创建子代理。
- 只要出现「跨文件/跨模块」「多阶段依赖」「批量检索或分析」「复杂调试或设计」「大量产物生成」「需要显著研究与验证」中的任意一项，即视为较复杂：由 GPT 规划，创建 Flash 执行子代理承担边界清晰的部分。
- **不得仅按回答字数或一次工具调用就判定复杂度**。
- 任务信息不足时，先作必要澄清再判定；澄清不等于授权，数据库写入、部署与破坏性操作仍须遵守用户授权与工具审批。

## 2. 派发前：先写自包含任务契约

较复杂任务在派发前必须先写出任务契约。契约必须自包含且至少覆盖六要素：

1. **目标**：要达成什么，可判定的完成态是什么。
2. **输入与上下文**：需要哪些文件、数据、前人结论；只给必要信息。
3. **范围**：允许修改/创建的确切位置（可写目录或文件清单）与禁止触碰的范围。
4. **约束**：环境、权限、工具限制、风格或接口约定、不可用的做法。
5. **交付物**：每个产物的确切路径与形态。
6. **验收标准**：在执行**之前**就写明检查方法与预期结果。

可填写模板与三类检验例（代码 / 分析 / 文档）见
`references/task-contract.md`（路径解析见第 8 节）。

同时遵守：

- 独立子任务可并行派发，但**可写范围不得重叠**；有依赖关系的工作按顺序进行。
- 只提供必要信息，**不要把无关凭据、密钥或整份含敏感信息的全局记忆复制进提示**。

## 3. 路由确认：现场查，不硬编码

每次会话**首次委派前**，以及配置改变或上次调用失败之后，必须用 `list_subagent_models` 现场确认可用的 provider、model 与支持的 reasoning_effort。

- 目标身份是 **DeepSeek V4.1 Flash**。**展示名可能与 API model id 不同**：不能凭展示名猜 model id，也不能凭旧会话的记录直接复用；以本次现场返回为准。展示名与预期不一致时，先确认身份再调用，不确定就不要派发。
- **不要把任何机器/账号专属的 provider、model 字符写死进流程**；本技能只规定「现场确认 + 显式传入」这一动作。
- **先区分「未能确认身份」与「确认不可用」**，再决定报告口径：
  - `list_subagent_models` 返回的目录是**建议性（advisory）**的：目录里没有某个 model id，**不等于**该 API 不可用——适配器可能接受未列出的 id。
  - 目标模型**不在目录中**、或目录未给出确切 model id 时：只报告「**未能确认目标模型身份**」，并列出本次实际查到的 provider/候选；**不要无证据断言 API 不可用，也不要凭展示名猜一个 id 后照旧派发，更不静默改模型**。此时应先向用户确认身份；确认不了就不派发。
  - 只有**有证据的失败**才报告不可用：`list_subagent_models` 工具本身报错/无法调用、调用目标模型返回认证失败、权限受限或明确的不存在错误等。此时如实报告具体阻碍并请用户选择，不得虚报已创建或已完成。
- **不得静默换模型**：不擅自换用其他 provider/model 顶替 Flash，未经授权不改主模型或全局默认子代理路由。

派发时必须**显式传入已现场确认的 provider 与 model**；**不得省略 provider/model 让子代理继承 GPT 主模型**。

`reasoning_effort` 取「该路由本次现场确认支持的档位」，不硬编码：

- 已确认支持 `high`：用 `reasoning_effort: "high"`（本流程默认档位）。
- 已确认支持其它档位、但**不支持 `high`**：改用**该路由已确认支持的档位**，或**省略 `reasoning_effort`** 让它用自己的默认档位——这两种做法都仍然**显式传入 provider/model**。不得因为「不支持 high」就判定这条合法渠道不可用，也不得为凑 high 而换到别的路由。
- 现场确认结果里**没有 effort 字段，或该路由未广告任何档位**（档位支持情况未知）：**省略 `reasoning_effort`**，用该路由自己的默认档位；**仍然显式传入 provider/model**。**不得因为「档位未知」就判定该路由不可用**，也不得因此换路由或换模型。
- 档位支持情况一律以本次现场确认结果为准；省略 effort 只是为了用该路由的默认档位，**不是**放弃显式传 provider/model。

调用形态（**示意**：下面的 provider/model/effort 全是占位符，代表任何真实路由，不得写死进流程）：

```
subagent({
  description: "<3-5 词任务名>",
  prompt: "<第 2 节的自包含任务契约全文>",
  provider: "<现场确认的 provider>",
  model: "<现场确认的 model>",
  reasoning_effort: "<现场确认支持的档位：确认支持 high 时填 \"high\"；支持其它档位时填该档位；不支持或未广告档位（含没有 effort 字段）时整行省略，用路由默认>"
})
```

## 4. 执行子代理的边界

- 使用普通 `subagent`，**不把普通子代理擅自升级为 Agent Teams**。
- **执行子代理不得递归委派**：契约中要写明这一点。
- **不得越权**：不做数据库写入、不做部署、不做破坏性操作，除非用户在本次任务中明确授权且工具审批通过。
- **不复制秘密**：不读取或转发用户全局凭据、密钥、私密配置文件的内容。
- **不得静默换模型**：子代理发现自己被路由到与契约不符的模型时，应停下并回报，而不是继续执行或自行替换。
- 子代理负责回报：产物路径与改动摘要、实际执行过的验证与结果、未完成项与风险；**子代理不能自行宣布用户任务最终验收通过**。

## 5. GPT 独立验收（不可外包）

收到子代理结果后，由 **GPT 主模型自己**完成验收：

- **自己 `read` 最终产物**（含关键源文件、diff/改动）并核对；**不得以子代理的日志、自述成功或它的测试输出代替验收**。
- **复跑适用的测试/构建/查询**（在权限与依赖允许时），比对预期与实际。
- 无法运行测试时，独立复核关键逻辑、事实、来源或数值，并**明确标注哪些验证未执行**；主观质量判断要说明依据，**不冒充客观测试通过**；环境受阻时不得声称全面通过。
- **不把独立验收整体再外包**给 Flash 或其他子代理。方案决策、权限边界、最终质量与验收结论的责任留在 GPT。
- 验收用到的检查项-方法-预期结果对照表见
  `references/acceptance-handoff.md`（路径解析见第 8 节）。

## 6. 验收不通过 → 返工 → 重验

- 验收不通过时，给出**具体失败证据、期望与实际的差异**，**先**通过 `send_message` 要求**原子代理（原执行子代理）**返工，再由 GPT 重新验收。
- 若 `send_message` 明确无法送达或恢复该原子代理（工具报错、目标不存在、会话已结束、`active teammate not found` 等）：**如实记录该事实**，重新用 `list_subagent_models` 现场确认 Flash 路由，再**新建替代 Flash 子代理**，把**原任务契约全文 + 本次失败证据**发过去，**只返工同一范围**。**不得静默换成别的模型顶替，也不得假装原子代理仍在继续**（不要靠反复 `send_message` 硬试）。
- **不得为交付降低标准**；也不得把「未验证」包装成「已通过」。
- 持续失败或条件不具备时（例如路由不可用、权限不足、替代子代理仍失败），如实交代并请用户决策。

## 7. 向用户交接

验收后由 GPT 现场向用户交接，内容至少包含：

1. 完成成果与可打开的文件链接（如有）。
2. 验收方式与结果（独立复跑了什么、看到什么）。
3. 剩余风险。
4. 未验证项（明确标注）。
5. 必要的使用或后续说明。
6. 一句话说明本次是 GPT 直接处理，还是 Flash 执行后由 GPT 验收。

未通过的项目明确标为未完成，**不包装成全部完成**。交接模板见
`references/acceptance-handoff.md`。

## 8. 读取参考文件：按 skill 工具返回的 base dir 解析

本技能引用两个参考文件：

- `references/task-contract.md`
- `references/acceptance-handoff.md`

**解析规则**：这两个路径是**相对技能包根目录**的相对路径。用 `skill` 工具加载 `gpt-flash-handoff` 时，工具返回值中的 **base dir（技能包根目录）** 才是解析基准；实际路径 = `<base dir>/references/task-contract.md` 等。

- 不要假定它们位于当前工作区、用户全局技能目录或任何固定机路径；**不要凭猜测的绝对路径去读**。
- 拿不到 base dir 时，先回到技能加载结果或技能目录中定位，再读取；找不到就如实说明，不要编造内容。

## 9. 用户明确禁止委派时优先

**若用户在当前任务中明确要求 GPT 自己完成、或明确禁止委派子代理，则本技能的派发环节全部失效**：GPT 直接执行，仍然保留第 5 节的自我核对与第 7 节的交接义务。用户指令优先于本技能的任何默认流程。

## 10. 后台任务与任务列表

- 记录每一个后台任务的 id；任务完成时会在会话内收到通知，**不要空转等待或轮询**，去做独立的下一步工作，也不要重复已在运行的任务。
- 给出最终结论前，用 `job_output` 收齐仍然相关的后台结果（只有确实被阻塞时才 `wait: true`），对已经不再相关的任务调用 `job_kill`。
- **任务列表必须反映真实最终状态**：完成一项就标记为 `completed`，不能只输出最终答案就结束而留下 `in_progress`。

## 11. 必需规则覆盖对照

| 规则 | 位置 |
