# 验收与交接模板（GPT 主模型独立使用）

本文件是 SKILL.md 第 5、6、7 节的配套模板。
**关键前提：验收由 GPT 主模型自己做，不能整体外包给 Flash 或其他子代理；子代理的自报成功与其测试日志仅供参考。**

---

## 一、验收记录模板（自己填，边验边填）

```
【被验收任务】<任务名>

【产物清单（自己 read 确认，不抄子代理自述）】
| # | 产物路径 | 存在 | 我实际读了什么 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | <路径> | 是/否 | <文件正文 / diff> | <符合/不符> |

【复跑的验证（我自己执行的）】
| # | 检查项 | 我执行的命令/动作 | 预期结果 | 实际结果 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 1 | <契约第 N 条> | <命令或动作> | <预期> | <实际> | 通过/不通过 |
| 2 | | | | | |

【无法执行的验证（必须显式标注，不得省略）】
- <检查项>：未执行，原因 <环境/权限/依赖缺失>；替代核对方式 <读代码/查来源>，结论 <...>

【主观质量判断（若涉及，说明依据）】
- <判断> —— 依据：<...>

【整体判定】通过 / 部分验证（部分检查未执行，或部分交付未完成）/ 不通过
【若不通过】失败证据（期望 vs 实际）：<...>
【若为部分验证或含未完成项】未执行的检查 / 未完成的交付，及各自原因：<...>
```

### 判定时的硬性要求

| # | 检查项 | 检查方法 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 读了真产物 | 自己 `read` 文件/diff | 不是只读子代理的总结 |
| 2 | 复跑了测试 | 自己执行适用测试/构建/查询 | 拿到原始输出，而非引用日志 |
| 3 | 契约逐条对齐 | 用契约验收表逐条比对 | 每条都有"实际结果"，无空项 |
| 4 | 越界检查 | 检查可写范围外的文件 | 未被改动 |
| 5 | 未验证项已列明 | 检查本记录「无法执行的验证」区 | 缺失的验证被写明，不伪装为通过 |
| 6 | 不冒充客观通过 | 检查主观判断是否标为"主观" | 无"看起来没问题所以通过"式表述 |

## 二、返工指令模板（验收不通过时，先 `send_message` 发给**原子代理**；送达失败时见下方替代流程）

```
验收不通过，请针对以下问题返工，不要扩大改动范围。

【失败项与证据】
1. 检查项：<契约第 N 条>
   期望：<契约写的预期结果>
   实际：<你观察到的实际结果 / 原始输出片段>
   复现方式：<我执行的命令或动作>
2. ...

【要求】
- 只修上述问题；不要顺手重构其它内容
- 修完自测并回报：改动摘要 + 你执行过的验证与原始结果
- 仍然不得递归委派、不得越权、不得静默换模型

【重验方式】我会再次独立 read 产物并复跑 <命令/动作>，不以你的日志为准。
```

**约束**：不得为交付降低标准；持续失败或条件不具备时（路由不可用、权限不足等）如实交代并请用户决策。

**原子代理不可达时的替代流程**：若 `send_message` 明确无法送达或恢复原执行子代理（工具报错、目标不存在、会话已结束、`active teammate not found` 等），**如实记录该事实**，重新用 `list_subagent_models` 现场确认 Flash 路由，再**新建替代 Flash 子代理**，把**原任务契约全文 + 上面的失败证据**发过去，**只返工相同范围**；**不得静默换成别的模型顶替，也不得假装原原子代理仍在继续**（不要靠反复 `send_message` 硬试）。

## 三、用户交接模板（验收后现场输出）

```
【本次方式】Flash 执行 + GPT 独立验收 / GPT 直接处理

【完成成果】
- <成果 1>：<一句话说明> → <可打开的文件链接>
- <成果 2>：...

【独立验收方式与结果】
- 我读了：<产物/diff>
- 我复跑了：<命令/动作> → <结果>
- 结论：<通过 / 部分验证（含未完成项）/ 不通过>

【剩余风险】
- <风险 1：触发条件 + 影响>

【未验证项（明确标注）】
- <项>：未执行，因为 <原因>

【未完成项】
- <项>：<当前状态与原因>（未通过的项目明确标为未完成）

【后续说明】
- <使用方式 / 建议的下一步>
```

### 交接前自查

| # | 检查项 | 检查方法 | 预期结果 |
| --- | --- | --- | --- |
| 1 | 链接可用 | 逐个确认所引文件确实存在 | 无死链 |
| 2 | 验收有证据 | 交接里写出"我读了什么、复跑了什么" | 不是"子代理说通过了" |
| 3 | 风险非空或已说明 | 检查风险节 | 有风险，或明确写"未发现明显风险"及依据 |
| 4 | 未验证项显式 | 检查未验证节 | 列出或明确写"无" |
| 5 | 不夸大 | 通读 | 未通过项未被包装成完成 |
| 6 | 后台与任务列表 | 收齐 `job_output`；核对 todo | 相关后台结果已收齐，todo 为真实最终状态（已完成项已标 `completed`） |

## 四、三类任务的检验例（与 `references/task-contract.md` 配套）

`references/task-contract.md` 已给出**代码 / 分析 / 文档**三类任务的契约检验例，并各附「验收时 GPT 自己要做什么」的检查项-方法-预期结果表。验收时按下表选取对应类型的检查重点，再补上本文件第一节的记录格式。

| 任务类型 | 验收重点（检查方法 → 预期结果） | 详见 |
| --- | --- | --- |
| 代码 | 自己读 diff；自己复跑测试与构建 → 通过且只改允许范围；边界输入不崩 | task-contract.md 第二节 |
| 分析 | 自己抽样回源核对引用；自己重算关键数值 → 与报告一致；口径与局限写明 | task-contract.md 第三节 |
| 文档 | 自己打开成品；自己核对事实与必含章节 → 覆盖完整、事实与来源一致、待确认项显式 | task-contract.md 第四节 |

## 五、常见误判（避免）

| 误判 | 为什么错 | 正确做法 |
| --- | --- | --- |
| "子代理说测试通过了" → 直接通过 | 自述与日志不能代替验收 | 自己复跑，拿原始输出 |
| 无法跑测试 → 说"已全面通过" | 冒充客观测试结果 | 标注"未执行"，改用逻辑/来源/数值复核 |
| 只看产物内容不查改动面 | 可能夹带越界改动 | 检查 diff 与可写范围 |
| 验收不通过但自己顺手改了 | 破坏"执行-验收"分离，掩盖问题 | 先 `send_message` 让原子代理返工，再重验；原子代理不可达时按第二节替代流程新建 Flash 子代理，不静默换模型 |
| 交接只写"已完成" | 用户无法判断可靠性 | 写清方式、证据、风险、未验证项 |
